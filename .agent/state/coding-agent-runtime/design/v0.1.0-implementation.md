# Verified v0.1.0 Implementation

## Status

`agentx` is implemented as a Go 1.25 single-binary CLI named `ax`, version `0.1.0`.

The verified implementation described here includes commits through `422043d`. The combined implementation passed `make verify`, covering formatting, `go vet`, tests, build, and smoke checks.

## Embedded cross-Agent sessions

**Conclusion:** CASR is no longer an Agent, Package, or external binary dependency. `ax` embeds an independently implemented Go session service for Claude, Codex, Gemini, OpenCode's JSON store, and Pi. All five providers support `providers`, `list`, `info`, and `resume`. Resume injects a bounded, normalized transcript through the target Agent's native command and never writes the target's private session database.

**Why:** Cross-Agent session behavior belongs to the runtime while native Agent stores remain the source of truth. Command-level transcript injection avoids coupling `ax` to private database schemas.

**Files:** `internal/sessions/service.go`, `internal/sessions/service_test.go`, `internal/app/app.go`, `internal/app/app_test.go`, `internal/drivers/registry.go`, `internal/drivers/package_registry.go`, `internal/drivers/package.go`, `internal/drivers/session.go`, `internal/runtime/types.go`

## Structured session output

**Conclusion:** Global JSON and YAML output cover session `providers`, `list`, `info`, and `resume --dry-run`. A real resume still executes the target Agent's native command.

**Why:** AgentX-owned discovery, inspection, and plans have one structured result protocol without wrapping native process output.

**Files:** `internal/app/app.go`, `internal/app/app_test.go`, `internal/runtime/types.go`

## Pi model availability filtering

**Conclusion:** `ax models pi` uses the dedicated `PiModels` driver. It reads provider records from Pi's native `${PI_CODING_AGENT_DIR:-~/.pi/agent}/auth.json`, recognizes only persisted `oauth` and `api_key` entries as logged in, strictly parses the six-column `pi --list-models` table, and returns canonical `provider/model` identifiers only for logged-in providers. Missing or empty auth yields an empty list. Malformed auth, external-command failure, or model-table format drift returns an explicit error. Environment variables and `models.json` do not count as logged-in authentication. The generic `CommandModels` driver is unchanged.

**Why:** Pi `--list-models` advertises models for providers that are not logged in, so unfiltered native output is not the set actually available to the user. Verified npm package `@mariozechner/pi-coding-agent@0.73.1` stores native auth entries under provider IDs and emits the table columns `provider`, `model`, `context`, `max-out`, `thinking`, and `images`.

**Files:** `internal/drivers/pi_models.go`, `internal/drivers/pi_models_test.go`, `internal/drivers/registry.go`

## Authentication

**Conclusion:** `AuthDriver` supports `login` and `status`. Claude, Codex, and OpenCode expose native status checks. Gemini and Pi explicitly report auth status as unsupported.

**Why:** Capability reporting follows verified native support; it does not infer auth state from interactive login flows.

**Files:** `internal/drivers/auth.go`, `internal/drivers/drivers_test.go`, `internal/app/app.go`

## Product lifecycle surface

**Conclusion:** The implemented lifecycle surface is deliberately bounded:

- Agent `list` performs discovery.
- Package supports `install` only.
- Model supports `list` and `select`.
- Launch supports `run` and dry-run planning.
- Session supports `providers`, `list`, `info`, and `resume`.
- Auth supports `login` and `status` as described above.

Logout and package update/uninstall are not product promises and must not be added merely to complete an abstract CRUD lifecycle.

**Why:** Drivers represent supported product operations rather than aspirational symmetry. Subtracting unsupported lifecycle states keeps capabilities orthogonal and truthful.

**Files:** `internal/runtime/types.go`, `internal/drivers/registry.go`, `internal/drivers/package.go`, `internal/drivers/auth.go`, `internal/drivers/launch.go`, `internal/drivers/models.go`, `internal/sessions/service.go`, `internal/app/app.go`

## CASR provenance boundary

**Conclusion:** Upstream CASR's license includes an OpenAI/Anthropic rider. `agentx` does not copy or embed CASR source code; its session service is an independent implementation.

**Why:** This preserves a clear implementation and licensing boundary while delivering the required cross-Agent behavior inside `ax`.

**Files:** `internal/sessions/service.go`, `internal/sessions/service_test.go`

## Other preserved runtime behavior

- Orthogonal runtime/driver structure; no giant all-capabilities adapter.
- Agent Registry contains Claude, Codex, Gemini, OpenCode, and Pi.
- Package installation plans cover those same five native Agent packages.
- Model sources remain native: Codex reads `models_cache.json`, OpenCode invokes `opencode models`, and Pi filters its strictly parsed `pi --list-models` table by persisted native auth providers; Claude and Gemini support selection without fabricated model listing.
- Launch maps `--model` to native invocations and passes arguments following `--` through to the native CLI.
- Agent location commands remain `ax list` and `ax which`.
- External process stdout/stderr remains native passthrough output. Debug logs remain JSON and include raw external input, output, and errors.
- There is no user-facing Profile schema or credential custody.
