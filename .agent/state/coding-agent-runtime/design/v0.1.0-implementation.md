# Verified v0.1.0 Implementation

## Status

`agentx` is implemented as a Go 1.25 single-binary CLI named `ax`, version `0.1.0`.

The lifecycle and protocol surface was re-audited on 2026-09-10 against the installed native CLIs and their bundled help/source. `make verify` includes `make audit`, which checks CLI grammar/documentation and capability/driver consistency in both directions.

## Embedded cross-Agent sessions

**Conclusion:** CASR is no longer an Agent, Package, or external binary dependency. `ax` embeds an independently implemented Go session service for Claude, Codex, Gemini, OpenCode's JSON store, and Pi. Those five providers support `providers`, `list`, `info`, and `resume`; AgentX has not implemented DSH session operations. Resume injects a bounded, normalized transcript through the target Agent's native command and never writes the target's private session database.

**Why:** Cross-Agent session behavior belongs to the runtime while native Agent stores remain the source of truth. Command-level transcript injection avoids coupling `ax` to private database schemas.

**Files:** `internal/sessions/service.go`, `internal/sessions/service_test.go`, `internal/app/app.go`, `internal/app/app_test.go`, `internal/drivers/registry.go`, `internal/drivers/package.go`, `internal/runtime/types.go`

## Structured output and errors

**Conclusion:** JSON and YAML cover AgentX-owned results and dry-run plans. A real install, login, logout, run, or session resume passes through native output and explicitly rejects `--json` or `--yaml`. Errors use the selected format with an envelope containing stable `code`, `message`, and `exit_code` fields; codes are `usage`, `unsupported_capability`, `external_command`, and `operation_failed`.

**Why:** AgentX-owned data has one structured protocol while native stdout/stderr remains unwrapped. Explicit rejection prevents output selectors from being silently ignored.

**Files:** `internal/app/app.go`, `internal/app/app_test.go`, `README.md`

## Pi model availability filtering

**Conclusion:** `ax agent models pi` uses the dedicated `PiModels` driver. It reads provider records from Pi's native `${PI_CODING_AGENT_DIR:-~/.pi/agent}/auth.json`, recognizes only persisted `oauth` and `api_key` entries as logged in, strictly parses the six-column `pi --list-models` table, and returns canonical `provider/model` identifiers only for logged-in providers. Missing or empty auth yields an empty list. Malformed auth, external-command failure, or model-table format drift returns an explicit error. Environment variables and `models.json` do not count as logged-in authentication. The generic `CommandModels` driver is unchanged.

**Why:** Pi `--list-models` advertises models for providers that are not logged in, so unfiltered native output is not the set actually available to the user. Local CLI and bundled-source inspection verified that native auth entries are stored under provider IDs and that the model table contains the columns `provider`, `model`, `context`, `max-out`, `thinking`, and `images`; this evidence does not identify the Registry's target npm package version.

**Files:** `internal/drivers/pi_models.go`, `internal/drivers/pi_models_test.go`, `internal/drivers/registry.go`

## Authentication

**Conclusion:** `AuthDriver` supports native `login`, `status`, and `logout` where native behavior is implemented. Claude, Codex, OpenCode, Gemini, and Pi support logout, using direct commands for Claude, Codex, and OpenCode and exact interactive instructions for Gemini. `ax auth login pi` invokes the installed Pi SDK's public `ModelRuntime.login(providerId, type, interaction)` through an embedded Node adapter. It offers OAuth subscription-provider selection or API-key login, hands required authentication interaction to the caller, and lets Pi synchronize credentials to its native `auth.json`; users no longer need to start Pi and enter `/login`. Existing provider entries in that file allow Pi to begin a session directly. AgentX has not implemented DSH authentication operations. `AuthStatus.providers` is always a list: Claude and Codex return zero or one provider, OpenCode and Pi return stored-provider lists, and Gemini and DSH status remain explicitly unsupported. Pi status and model filtering share `PiAuthFileProviders` as their native credential source.

**Why:** Pi SDK publicly provides the authentication API, so AgentX can retain Pi's native credential ownership while presenting a direct login flow. `make verify` passed after the adapter integration. Provider-list status represents both single-account and provider-scoped Agents without credential custody or conflicting auth conclusions.

**Files:** `internal/runtime/types.go`, `internal/drivers/auth.go`, `internal/drivers/registry.go`, `internal/drivers/pi_models.go`, `internal/drivers/pi_sdk_login.go`, `internal/drivers/pi_sdk_login.mjs`, `internal/drivers/drivers_test.go`, `internal/app/app.go`, `README.md`, `docs/lifecycle-and-protocol-audit.md`

## Product lifecycle surface

**Conclusion:** The implemented lifecycle surface is deliberately bounded:

- Agent supports `list`, `which`, `install`, `models`, and `run`; resources lead the CLI hierarchy.
- Each Agent owns its install driver. The duplicative `PackageRegistry` and separate package resource are deleted.
- Model supports `list` and `select`.
- Launch supports `run` and dry-run planning.
- Session supports `providers`, `list`, `info`, and `resume`.
- Auth supports `login`, `status`, and `logout` as described above.

Package status, update, and uninstall are not product promises and must not be added merely to complete an abstract CRUD lifecycle. Agent detection already supplies installed status. Session source selection is uniformly named `--source`; destructive native session operations are not normalized because the five native lifecycles lack shared semantics.

**Why:** Drivers represent supported product operations rather than aspirational symmetry. Subtracting unsupported lifecycle states keeps capabilities orthogonal and truthful.

**Files:** `internal/runtime/types.go`, `internal/drivers/registry.go`, `internal/drivers/package.go`, `internal/drivers/auth.go`, `internal/drivers/launch.go`, `internal/drivers/models.go`, `internal/sessions/service.go`, `internal/app/app.go`, `internal/app/consistency_test.go`, `Makefile`

## Direct daily entry points

**Conclusion:** `ax <agent>` is a top-level shortcut for `ax agent run <agent>`. Bare `ax` starts an interactive resume flow: choose either current-workspace or all-workspaces session scope, select a recent session, select an installed target Agent, then select a model. README's canonical onboarding narrative leads with `ax codex` for new work and bare `ax` for interactive resume. The existing resource-first long commands remain available and authoritative, but documentation relegates them to management, explicit control, and command reference.

**Why:** The most common daily operation is starting a Coding Agent. These zero-migration shortcuts implement the uv-inspired low-friction entry wedge without replacing native session stores, native commands, or the explicit resource-first grammar. That daily entry point must be the primary onboarding story rather than a shortcut patched onto a long-command-first narrative.

**Files:** `internal/app/app.go`, `internal/app/app_test.go`, `README.md`, `internal/app/consistency_test.go`

## CASR provenance boundary

**Conclusion:** Upstream CASR's license includes an OpenAI/Anthropic rider. `agentx` does not copy or embed CASR source code; its session service is an independent implementation.

**Why:** This preserves a clear implementation and licensing boundary while delivering the required cross-Agent behavior inside `ax`.

**Files:** `internal/sessions/service.go`, `internal/sessions/service_test.go`

## Other preserved runtime behavior

- Orthogonal runtime/driver structure; no giant all-capabilities adapter.
- Agent Registry contains Claude, Codex, Gemini, DSH, OpenCode, and Pi.
- Installation plans belong directly to those same six Agent registry entries; DSH uses `@deepseek-ai/dsh`.
- Model sources remain native: Codex reads `models_cache.json`, OpenCode invokes `opencode models`, and Pi filters its strictly parsed `pi --list-models` table by persisted native auth providers; Claude and Gemini support selection without fabricated model listing. AgentX has no DSH model capability; DSH's native model-related components are verified, but no AgentX CLI mapping is implemented.
- Launch maps `--model` to native invocations when an Agent supports model selection; DSH launches raw native `dsh`. All Agents pass arguments following `--` through to the native CLI.
- The CLI's authoritative grammar is resource-first: `ax agent ...`, `ax auth ...`, and `ax session ...`; action-leading commands and plural aliases are removed. Top-level `ax <agent>` and bare interactive `ax` are intentional daily-use shortcuts.
- External process stdout/stderr remains native passthrough output. Debug logs remain JSON and include raw external input, output, and errors.
- There is no AgentX-owned user-facing Profile schema or credential custody. This does not exclude native profile or credential mechanisms provided by an integrated Agent such as DSH.
